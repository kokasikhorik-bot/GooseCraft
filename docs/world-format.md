# GooseCraft world format 1

Это собственный формат `.gcw`, не Anvil/NBT и не совместимость с Minecraft.
В мире пока один или девять чанков по 16³, два непрозрачных материала и воздух.
Формат сохраняет только блоки; положение игрока, GPU-данные, очередь обновлений
и счётчики не сохраняются. Изменение схемы потребует другой версии формата.

## Байты

| Смещение | Размер | Значение |
| --- | ---: | --- |
| 0 | 8 | ASCII `GOOSEWLD` |
| 8 | 1 | Версия: 1 |
| 9 | 1 | Радиус чанков: 0 или 1 |
| 10 | 1 | Число чанков: 1 или 9, согласно радиусу |
| 11 | 1 | Зарезервировано, обязательно 0 |
| 12 | 4 | Adler-32, little-endian |
| 16 | 4096 × число чанков | Неупакованные ID блоков: 0, 1, 2 |

Checksum считается по байтам `[0,12)` и `[16,end)`, стандартный Adler-32:
начальные A=1/B=0, модуль 65521. Это проверка случайного повреждения, не
криптографическая аутентификация. ID 0 — воздух, 1 — зелёный, 2 — янтарный;
это собственные ID, не реестр Minecraft.

Чанки идут по Z, затем X, от координат -radius до +radius.
При радиусе 0 хранится только чанк (0,0). Внутри чанка индекс блока:
`x + 16*(z + 16*y)`. Все координаты целые, локальные 0..15.
Файл содержит ровно 4112 или 36880 байт. Хвосты, усечения, неизвестные
версии, неверный размер/счётчик, checksum и неизвестные ID отвергаются.

`decode` сначала проверяет всё содержимое, затем заменяет мир. При ошибке
сохраняет старые блоки, revision и dirty-флаги. При успехе все активные
чанки помечаются для построения меша. `encode` не меняет мир и не создаёт
файл при неподдерживаемых ID.

## Запись на диск

Код на Goose использует реальные `os.read_file`, `os.write_file_atomic`,
`os.make_dir`, `os.env` из закреплённой stdlib. `write_file_atomic` записывает
временный соседний файл, сбрасывает данные и переименовывает его поверх
целевого. Ошибка записи не должна обнулить предыдущую версию; оставшиеся
ошибки и поведение файловой системы возвращаются вызывающему коду.

Текущий `os.read_file` читает целый файл до вызова декодера. Проверка точного
размера в декодере не является ограничением памяти на чтение произвольно
большого входного файла. Ограниченное потоковое чтение — отдельная будущая
работа; формат сейчас предназначен для локальных сохранений прототипа.

Headless-тесты проверяют roundtrip, атомарную замену, ошибки родительского
каталога, сохранность постороннего файла, испорченный ввод и UTF-8 пути с
пробелами/кириллицей. Python независимо проверяет заголовок и checksum через
zlib; байты TinyCC/native и release/debug должны совпадать.

Консольный клиент умеет читать без графики:
`goosecraft-headless --headless --inspect-world FILE`.
Успех возвращает JSON с числом чанков и блоков. Неверный/нечитаемый файл —
exit 5, исходный файл не изменяется.
