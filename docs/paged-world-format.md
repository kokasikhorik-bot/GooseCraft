# Каталог мира GooseCraft: формат 3

Отдельный opt-in backend `--paged-world DIR`. Это собственный конечный
voxel-мир, не Minecraft Anvil/NBT и не сетевой протокол. Высота 16, radius
0..4 в индексе, собственные ID 0/1/2. Новый GUI-мир обычно radius 4, seed 12345.
Каталог хранит `index.gci`, `world.lock` и страницы `chunk_X_Z_GENERATION.gcp`.
Файлы GCW v1/v2 не меняются; обычный `--world FILE` использует прежний backend.

## Индекс: ровно 1024 байта

Все числа little-endian. Adler32, как в GCW, считается по `[0,12)` и `[16,end)`.

| Offset | Bytes | Значение |
| --- | ---: | --- |
| 0 | 8 | ASCII `GOOSEIDX` |
| 8 | 1 | 3 |
| 9 | 1 | Radius 0..4 |
| 10 | 1 | Generator 1: известный seed рельефа v1; 0: импорт без известного seed |
| 11 | 1 | 0 |
| 12 | 4 | Adler32 всего индекса без checksum field |
| 16 | 4 | Seed u32; при generator 0 обязательно 0 |
| 20 | 4 | Commit serial 0..2147483647 |
| 24 | 4 | Число активных чанков 1/9/25/49/81 |
| 28 | 4 | 0 |
| 32 | 972 | 81 запись по 12 байт: generation u32, page checksum u32, solid count u32 |
| 1004 | 20 | 0 |

Активные slots используют прежний порядок Z, затем X. Ширина
`2*max(radius,1)+1`; radius 0 имеет только активный центр slot 4.
Неактивные записи полностью нулевые. Solid count 0..4096, generation не больше
serial. Generation 0 допустим только с generator 1: страницы нет, её блоки
детерминированно получаются из seed/координат. Page checksum тогда 0, а solid
count всё равно известен. У импортированного мира все активные pages явные.

## Страница: ровно 4128 байт

| Offset | Bytes | Значение |
| --- | ---: | --- |
| 0 | 8 | ASCII `GOOSEPG3` |
| 8 | 4 | Байты 3,0,0,0 |
| 12 | 4 | Adler32 страницы без checksum field |
| 16 | 4 | X чанка, signed i32 |
| 20 | 4 | Z чанка, signed i32 |
| 24 | 4 | Generation, совпадает с индексом и именем |
| 28 | 4 | Solid count, совпадает с индексом и payload |
| 32 | 4096 | Raw ID 0/1/2, индекс `x + 16*(z + 16*y)` |

Чтение проверяет размер, magic, reserved bytes, координаты/generation,
checksum страницы и ссылку из индекса, ID и число блоков до замены чанка.
Adler32 обнаруживает случайное повреждение, не является аутентификацией.
Сумма count записей позволяет сообщить общий мир без резидентности всех блоков.

## Публикация и блокировка

Один сеанс GooseCraft удерживает `world.lock`: Windows `CreateFileW` без
sharing, POSIX `flock(LOCK_EX|LOCK_NB)` на отдельном descriptor. Второе открытие
GooseCraft отказывается с exit 8. На POSIX lock advisory; сторонние редакторы
и внешние изменения файлов во время сеанса не поддерживаются. Пустой lock-файл
остаётся после выхода, ОС освобождает блокировку при закрытии/завершении процесса.

Commit записывает изменённые резидентные чанки в новые generation-файлы через
реальный Goose `os.write_file_atomic`, затем атомарно заменяет `index.gci`.
Только после успеха обновляет живые ссылки и снимает changed. На ошибке живой
пул/правки сохраняются, прежний индекс не заменяется. Частично созданные новые
страницы не упоминаются прежним индексом. Retry может заменить такие orphan
файлы; опубликованные старые страницы не перезаписываются. Сборщика старых
generations/orphans пока нет: диск со временем растёт.

Это опирается на атомарное переименование и flush в pinned stdlib/файловой
системе. Проверялись отказы записи страницы и публикации, не реальная потеря
питания, все файловые системы или power-loss durability. Индекс ссылается
только на полностью записанные страницы; без индекса незавершённый каталог
не считается миром и не дополняется автоматически при обычном открытии.

## CPU-пул и ошибки

`world::Paged` имеет **49 фиксированных Chunk**: 200704 байта блоков.
Metadata индексирует максимум 81 чанк, но не содержит их payload. CPU-квадрат
имеет радиус `mesh_radius+1`: он даёт полный halo для GPU-мешей. Стартовый
чанк (0,0) дополнительно закреплён для безопасной физики respawn. В нынешнем
конечном мире из-за обрезки по краям это также укладывается в 49 slots;
проверены все 81 положения. `--mesh-radius` здесь 1 или 2, полный preview,
demo/single и `--retain-meshes` несовместимы.

Перед изменением пула входящие данные проверяются по одной странице.
Перед вытеснением изменённых CPU-чанков фиксируются все pending-правки.
Потом снимаются старые mappings и новые страницы читаются в свободные slots.
Первый preflight или write failure не меняет пул. Если внешняя I/O-ошибка
возникла между preflight и повторным чтением, игра останавливается до
использования отсутствующих блоков; отсутствующий чанк никогда не считается
воздухом. Frontend при exit 8 пытается checkpoint pending-правок. Если запись
тоже недоступна, несохранённые изменения могут потеряться, последний
опубликованный индекс сохраняется. F5 остаётся полезным.

Ограниченное чтение выполняет небольшой собственный C-слой OS I/O;
формат, checksum, генерация, индекс, политика и игра — на Goose. Он принимает
caller-owned slice, проверяет EOF, не выделяет память по длине файла.
Индекс читается в 1024, страница в 4128 байт; malformed файл 1 ГБ отвергнут
native/JIT. Пути UTF-8, Windows переводится в UTF-16; лимит нативного helper
4095 UTF-8 байт полного пути. I/O синхронное; асинхронных workers пока нет.

49 слотов — не полный RSS. Scratch buffers, metadata, profiler, allocator,
GPU/driver живут отдельно. Для маленького импортированного мира фиксированный
пул может быть больше прежнего полного Map; автоматической миграции нет.
Мир остаётся конечным 144×144 максимум, seed не означает бесконечную генерацию.

## Перенос и экспорт

```bat
goosecraft.cmd --headless --create-pages 12345 NewPages
goosecraft.cmd --headless --import-world Old.gcw ImportedPages
goosecraft.cmd --headless --inspect-pages ImportedPages
goosecraft.cmd --headless --export-pages ImportedPages NewBackup.gcw
goosecraft.cmd --paged-world ImportedPages
```

Создание/импорт требует нового каталога. Импорт полностью проверяет исходный
GCW в буфере не более 331792 байт, записывает страницы и публикует индекс
последним. Исходный GCW остаётся побайтно прежним; seed не угадывается.
Повторный импорт в существующий каталог отвергается. Export проверяет все
страницы и создаёт новый GCW v1/v2; существующий файл не заменяет.
Импорт/экспорт — bulk-операции: временно используют полный Map/буферы и не
ограничены рабочим пулом 49. Проверен обратный побайтный переход для 1/9/81
чанков. При ошибке нового импорта остаётся незавершённый каталог без индекса.

Диагностические файлы в paged GUI: новые `.png` screenshots, `.json` profiles.
Их имена не могут совпасть с index/page/lock файлами. Режим по-прежнему
не сохраняет позицию игрока и не подключается к Minecraft-серверам.
