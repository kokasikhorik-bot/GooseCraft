# GooseCraft 0.6.1 — согласование рёбер меша

Два просвета из [0.6](terrain-results.md) больше не наблюдаются в проверенных
обзорах рельефа. Исправление написано на Goose, мир/seed/GCW не меняются.
Это исправление корректности с измеримой ценой; ускорение FPS не заявляется.

![Исправленный обзор seed 12345, настоящий Linux lavapipe readback](validation/stitch/terrain-preview.png)

## Изменение геометрии

Длинная сторона greedy-прямоугольника могла проходить через угол соседнего
прямоугольника, не имея вершины в этой точке: T-стык. Математическая поверхность
полная, но независимые рёбра после проекции и растеризации могут оставить
одиночный пустой пиксель. Простая перестановка расчёта матрицы/мирового origin
была проверена отдельно и не изменила шесть исходных расхождений.

`src/core/stitch.goose` обрабатывает исходные quad-меши после `mesh::build`:

1. Отмечает углы в сетке 17³. При отсутствии крупных прямоугольников сразу
   возвращается: пустота и checkerboard сохраняют исходные данные.
2. Добавляет точки в длинное ребро, если там есть угол другого патча.
   На шести границах чанка рёбра делятся на единичные сегменты: независимо
   перестроенные соседи используют одни и те же позиции.
3. Только затронутый прямоугольник получает центральную вершину и веер
   треугольников. Остальные сохраняют четыре вершины/два треугольника.

Размеры блоков, цвет/материал, поверхность и winding сохраняются. Нет
раздувания полигонов, depth bias или маскировки дыр цветом фона. Дополнительные
атрибуты будущих текстур/AO потребуют корректного вычисления на новых вершинах;
сейчас цвет грани постоянен. Это не заявленная поддержка будущих материалов.

Фиксированные массивы постпроцесса: 4913 bool и 64 u32, логически 5169 байт.
Это не размер всего C stack/памяти клиента: есть служебные значения и растущие
массивы выхода. Общие CPU/GPU-буферы и dirty-бюджет два чанка за кадр сохранены.
Постпроцесс выполняется при построении/правке чанка, не каждый кадр.
Единичные сегменты на внешних рёбрах не зависят от greedy-разбиения соседнего
чанка. Поэтому правка внутри чанка по-прежнему не требует перестраивать
соседа только ради обновившегося разбиения; правило dirty-флагов сохранено.

`--raw-greedy` отключает постпроцесс и воспроизводит старый дефект;
`--reference-renderer` использует единичные грани. Эти режимы взаимоисключающие.
`--preview-view 0..3` выбирает диагностический обзор, применяется с preview
или offscreen. Обычное управление игроком не изменилось.

## Проверки поверхности и изображения

Восемь headless suites проходят без DISPLAY в TinyCC JIT и native AOT,
release/debug, локально на GCC 14.2 и GCC 12.2 в закреплённом Docker.
Прежние mesh/terrain/GCW проверки сохранены. Новый `tests/stitch.goose`:

- Независимо клиппирует реальные индексированные треугольники к единичным
  квадратам поверхности. Площадь каждой ожидаемой клетки равна 1 с допуском
  1e-7 для f64 clipping; цвет, ориентация и отсутствие лишней поверхности
  сверяются с reference, а не с устройством веера.
- Ищет любую вершину строго внутри ребра треугольника на полушаговой сетке.
  Проверяет и отдельные чанки, и собранный мир 3×3, включая отрицательные
  мировые координаты после общего переноса в положительную область теста.
- Проверяет четыре seed, пустоту, платформу, столбики и checkerboard;
  специально отвергает исходный T-стык, удалённый и дублированный треугольники.

Графический `render-test` прошёл **75 сценариев** в Docker без сети,
Mesa lavapipe/X11/Xvfb. На 16 обзорах (четыре seed × четыре стороны) у нового
меша и reference нет clear-пикселей, замкнутых внутри сплошного рельефа.
Проверка — 8-связный flood fill цвета неба от границы кадра, только для
неотредактированных heightfield-сцен. Реальные вырытые отверстия этим правилом
не проверяются. Raw control обязан воспроизвести оба исходных просвета:
(433,160) и (327,312), иначе тест не считается успешным.

Попиксельная эквивалентность всех обзоров **не заявляется**. На исходном
ракурсе остаются два различия цвета; на всех 16 — от 0 до 5. Каждое различие
должно находиться на общей 3×3 границе двух цветов в обоих изображениях;
новый тест ограничивает их число восемью. Прежние строгие проверки плоских
сцен (не более четырёх только silhouette-пикселей) не ослаблены; в этом прогоне
все пять таких сравнений совпали точно, включая игровые replay.

Window/offscreen и release/debug дают одинаковые PNG в исходном и обратном
обзорах, а также в игровых сценариях. Движение, редактирование, dirty-чанки,
F5/exit save и reopen продолжают проходить. API misuse count = 0; отдельный
Khronos validation layer не установлен. Windows GUI/физический GPU не проверены.

## Цена исправления

Начальный рельеф seed 12345, все девять чанков:

| Показатель | Raw greedy 0.6 | Согласованный 0.6.1 | Reference |
| --- | ---: | ---: | ---: |
| Прямоугольники до постпроцесса | 817 | 817 (394 изменены) | 6698 |
| Вершины | 3268 | 6208 | 26792 |
| Индексы | 4902 | 14904 | 40188 |
| Полезные vertex/index байты | 71896 | 158944 | 589424 |
| Запрошенная ёмкость mesh GPU-буферов | 101376 | 225280 | 589424 |

Полезные данные выросли в 2,21 раза относительно raw, но остаются в 3,71 раза
меньше reference. Это только геометрия: не вся RAM/VRAM, не экономия всего
клиента. В одночанковом edit replay загружено 29096 байт против 163680
у reference — примерно в 5,63 раза меньше. Старый контракт 10× для raw-меша
сменён на 5× для исправленного; GPU-буферы по-прежнему переиспользуются
(2 выделения против 6 в этом replay).

`benchmarks/stitch.goose`: native release, 7 samples × 1000 iterations,
8 warmup builds на чанк, порядок трёх алгоритмов циклически меняется.
`os.clock_ns` monotonic. Halo подготовлены до таймера; generation, snapshot,
GPU и кадры не входят в замер. Медиана микросекунд на полный вход:

| Сцена | Чанков | GCC 14 reference / raw / stitched | GCC 12 reference / raw / stitched |
| --- | ---: | --- | --- |
| empty | 1 | 1.163 / 1.374 / 1.388 | 1.436 / 1.521 / 1.531 |
| flat | 1 | 8.182 / 5.133 / 7.991 | 8.074 / 5.664 / 8.505 |
| full | 1 | 48.811 / 39.452 / 43.887 | 49.585 / 39.884 / 44.031 |
| demo | 1 | 8.668 / 6.236 / 10.437 | 8.525 / 7.179 / 11.420 |
| terrain-region | 9 | 226.645 / 229.257 / 298.555 | 243.224 / 243.970 / 310.924 |
| checker | 1 | 131.729 / 155.874 / 173.604 | 128.187 / 124.556 / 142.152 |

Для рельефа CPU-построение медленнее raw примерно на 30% (GCC 14) / 27%
(GCC 12), и медленнее reference. Checkerboard не уменьшается по геометрии
и тоже платит за дополнительный обход. Тайминги — наблюдения одного облачного
хоста, не CI performance gate и не сравнение с Minecraft. Исправлена
корректность, а не доказано увеличение FPS. Следующий большой мир потребует
профилирования кадров/загрузки и дальнейшего сокращения работы.
