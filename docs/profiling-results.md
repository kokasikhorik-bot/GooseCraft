# GooseCraft 0.7 — проверяемые измерения игрового цикла

Реализованы [профиль на Goose и схема JSON](profiling.md), p50/p95/p99,
границы стадий, ограниченный буфер и безопасная выгрузка. Из обычного выхода
удалён незапрошенный GPU readback. Мир остаётся 48×16×48: это подготовка
профилирования перед расширением, не новый потоковый мир или сетевой клиент.
GCW v1 и фиксированные SHA-256 четырёх seed не изменились.

## Реальные проверки

Девять headless suites: TinyCC/native AOT, release/debug; локально прошли
GCC 14.2 и GCC 12.2 в закреплённом Docker. Новый suite проверяет прогрев,
нулевую/единственную выборку, nearest rank, неверные длительности/флаги,
сохранение состояния при отказе, rollover 1100 → последние 1024 samples,
JSON I/O с пробелами/кириллицей, отказ заменить существующий профиль и ошибки
родительского пути. Native/JIT JSON синтетического fixture совпадает побайтно.
Python пересчитывает каждую summary из raw rows, включая p99 и mean.
Синтетические ns этого unit fixture не выдаются за замеры производительности.

В Docker без сети прошли **84 сценария** lavapipe/X11/Xvfb. Прежние 75
проверок поверхности, T-стыков, GPU readback, dirty, игрока, сохранений и
reference сохранены. Добавлены девять запусков с профилем: window/offscreen,
debug, reference, неподвижный игрок, короткий прогрев, 1100 кадров для rollover,
F5 и replay с паузами/потерей фокуса.

Включение профиля сохранило SHA-256 PNG и игровое состояние детерминированных
replay. В данных найдены две правки/перестроения, 14 paused frames отдельного
сценария и один F5 в сохраняемом мире. Измеренные uploads/создания буферов
сверены с cumulative-счётчиками клиента. Каждый sample соблюдает бюджет
не более двух remesh и соответствует действительным draw calls.

Без screenshot клиент сообщает `colored_pixels=-1`/`readback_performed=false`,
а `exit_readback_ns=0`. При неудаче выгрузки профиля exit 7 исходный посторонний
файл сохранён, а мир уже записан и читается независимым headless-клиентом.
Существующий профиль отвергается до GPU; это проверяет и Windows render-build.

## Что показал облачный замер

Это один локальный прогон pinned Linux/Debian Mesa lavapipe (CPU Vulkan),
640×480. Метрики — wall time клиентского CPU-цикла, не GPU timestamp/FPS.
Детерминированный ввод моделирует 1/60 s, часы профиля настоящие.

| Сценарий | Retained | p50 / p95 / p99 цикла, ms | Финальный flush, ms |
| --- | ---: | --- | ---: |
| terrain replay / offscreen release | 120 | 0.0320 / 0.1509 / 0.6834 | 227.426 |
| terrain replay / Xvfb window release | 120 | 1.9425 / 2.0992 / 4.0998 | 0.788 |
| terrain replay / offscreen debug | 120 | 0.0441 / 0.3073 / 1.3968 | 100.311 |
| terrain replay / offscreen reference | 120 | 0.1511 / 0.2076 / 0.3280 | 118.056 |
| idle / window, warmup 30 | 150 | 1.3335 / 1.5574 / 18.5040 | 0.780 |
| preview / offscreen, 1100 frames, warmup 3 | 1024 | 0.0523 / 0.0839 / 0.1249 | 3377.045 |

Offscreen без swapchain быстро ставит работу в очередь. Короткий CPU-цикл
сочетается с долгим окончательным ожиданием GPU; считать обратную величину
0.032 ms игровым FPS было бы ошибкой. Window `pump_ns` включает ожидание
показа/очереди предыдущего кадра. Эти режимы нельзя сравнивать как одинаковый
рендеринг на физической видеокарте. Различие release/debug/reference в одном
шумном прогоне также не доказывает ускорение одного варианта.

Для window terrain replay p50 стадий: pump 1.91967 ms, game 0.00439 ms,
mesh 0.00005 ms, save check 0.00002 ms, submit 0.01596 ms. Большинство кадров
не перестраивает чанки; mesh p99 0.06966 ms показывает редкие правки лучше,
чем p50. Эти отдельные процентили не складываются в общий процентиль.
Первичная подготовка мешей 0.785833 ms входит в startup 33.027685 ms.

Дополнительный collector в этом window capture занял суммарно 9140 ns на
120 кадров (около 0.076 us/кадр). Это измеренный интервал чтения счётчиков и
записи sample после основного замера; он не доказывает такую же полную цену
профилирования на других машинах. Клиент записал целую сессию цикла отдельно.

Контроль памяти: samples 98304 байта, block capacity 36864, mesh capacity
225280, overlay capacity 524672. Это известные логические/запрошенные ёмкости,
не суммарная RAM/VRAM. Capture с screenshot дополнительно потратил 4.811093 ms
при выходе на readback/проверку/PNG; обычный запуск этот этап пропускает.

## Evidence и следующий этап

[Raw profiles](validation/profiling/profiles/),
[проверки и summary](validation/profiling/profiling-results.json),
[результаты рендера](validation/profiling/render-results.json) и логи сохранены
в Git. Длительности не являются performance gate: CI проверяет данные и
инварианты, а не скорость общей облачной машины.

Дальше — расширение представления мира/загрузки чанков с использованием этих
метрик, профилирование памяти процесса и платформенный GPU timing при наличии
подтверждённого API. Фиксированный бюджет два чанка пока не является временным
бюджетом миллисекунд. Сравнение с Minecraft потребует равных условий и мира.
Windows 10 GUI и физическая видеокарта ещё не проверены; итог Windows CI
фиксируется в [github-ci.md](github-ci.md).
