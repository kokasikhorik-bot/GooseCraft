# GCW v4 — мир высотой 64 блока

Это собственный формат GooseCraft, не Minecraft Anvil. Включается отдельно:

```bat
goosecraft.cmd --tall-world Tall.gcw --radius 4
```

Новый мир имеет Y **−16..47**, четыре секции 16×16×16 на колонку. Радиус
0/1/2/3/4 означает 1/9/25/49/81 колонку, 4/36/100/196/324 активных секции.
GUI создаёт радиусы 1..4; headless также поддерживает 0. Горизонтальные границы
прежние: `[-radius*16, (radius+1)*16)`. Мир конечный и полностью резидентный.
Страницы v3 и их worker здесь не используются; обычные GCW v1/v2 и directory v3
продолжают открываться своими режимами без изменения байтов.

## Заголовок, 48 байт

Все многобайтные числа little-endian. Adler-32 считается по всему файлу,
исключая байты 12..15, как в прежних GCW.

| Offset | Размер | Значение |
| --- | ---: | --- |
| 0 | 8 | `GOOSEWLD` |
| 8 | 1 | version 4 |
| 9 | 1 | radius 0..4 |
| 10 | 1 | section layers 4 |
| 11 | 1 | zero |
| 12 | 4 | Adler-32 |
| 16 | 4 | количество активных секций, 4×число колонок |
| 20 | 4 | signed min Y = −16 |
| 24 | 4 | signed upper Y exclusive = 48 |
| 28 | 4 | generator 0 (неизвестен/перенос) или 2 |
| 32 | 4 | seed u32; для generator 0 обязательно 0 |
| 36 | 12 | reserved zero |

Далее полные payload активных секций по 4096 bytes, IDs 0/1/2. Сначала весь
слой cy=−1, затем 0, 1, 2; внутри слоя cz, затем cx по возрастанию.
Локальный индекс — `x + 16*(z + 16*y)`. Для radius 0 записываются только
четыре центральные секции. Длина строго `48 + sections*4096`, максимум
**1 327 152 байта**. Воздух тоже хранится явно. Seed — metadata происхождения,
а не разрешение восстановить отсутствующий/усечённый payload.

Goose до замены live world проверяет magic/version, radius/layers/range,
count, generator/seed, reserved, точную длину, checksum и все material IDs.
Чтение ограничено максимальным размером через `fileio.read_bounded`.
Единственное изменение C — общий I/O ceiling с 1 до 2 MiB; кодека, координат
и генератора в C нет. Helper `read_exact` сохранил предел 16 KiB.
Сохранение использует прежний `write_file_atomic` после полной encode-проверки.
Как и старый full Map backend, этот режим пока не вводит отдельную world lock.

## Явный перенос старых миров

```bat
goosecraft.cmd --headless --generate-tall 12345 NewTall.gcw --radius 4
goosecraft.cmd --headless --inspect-tall NewTall.gcw
goosecraft.cmd --headless --import-tall Old.gcw MigratedTall.gcw
goosecraft.cmd --tall-world MigratedTall.gcw
```

Перенос принимает GCW v1/v2 всех поддерживаемых радиусов, полностью проверяет
ввод и требует нового пути. Сохраняет все прежние блоки в Y 0..15 и radius;
нижняя и две верхние секции заполняются воздухом. Header generator/seed = 0/0,
поскольку старые GCW не хранят seed. Исходный файл не меняется. Это расширение
диапазона, а не регенерация окружения; новые горы в перенесённом мире не появляются.
Обратного экспорта высокого мира в старый формат пока нет.

Для directory v3 сначала экспортируйте старый мир в новый GCW v1/v2:
`goosecraft.cmd --headless --export-pages OldPages OldExport.gcw`, затем выполните
`--import-tall OldExport.gcw MigratedTall.gcw`. Каталог v3 не меняется.

`--tall-world` не открывает старый GCW напрямую; `--world` не открывает v4.
Оба неправильных режима дают 5 и сохраняют исходные байты. Новое создание
не заменяет существующие пути. Seed и radius нельзя менять при повторном
открытии. Diagnostics требуют новый `.png` и `.json`, чтобы не заменить save.

## Генератор 2 и стоимость

Новый рельеф использует прежний проверенный integer noise:
`height2 = 12 + 2*height1 + noise(seed xor 0x68bc21eb, x,z,32)*8/256`.
Заполняет Y от −16 до `height2-1`, верх — green, ниже — amber. RNG/float
в генерации нет. Generator 1 и его контрольные векторы не менялись.
Пять SHA-256 vectors v2/radius 0/1/2/4 сверяются с независимым Python test oracle
и Goose TinyCC/native. Python не участвует в игровом клиенте.

324 секции требуют **1 327 104 байта block payload**: в четыре раза больше
полного старого Map того же radius. Для radius 0 минимальный внутренний pool
остаётся 3×3, поэтому физически выделены 36 слотов при четырёх активных.
GPU residency по-прежнему выбирается по X/Z: при mesh radius 2 до 100 готовых
секций вместо 25 старых чанков; пустая секция может не иметь GPU buffers.
После startup rebuild budget — две секции за кадр. Флаговые массивы renderer
расширены до 324 элементов; старые CPU Map/Paged payload не увеличивались.
Это функциональный этап, не подтверждённое уменьшение RAM/FPS относительно
Minecraft. Вертикальный paging, sparse sections, modern 384-block height,
освещение и сетевой адаптер ещё требуют отдельных этапов.
