# Архитектура GooseCraft

```text
GooseCraft/
├── src/
│   ├── client.goose          # независимый headless-клиент
│   ├── viewer.goose          # графический клиент, CLI и явный import gfx
│   ├── core/
│   │   ├── core.goose        # входной модуль пакета core
│   │   ├── world.goose       # growable-владелец 1..81 чанка, dirty и halo
│   │   ├── terrain.goose     # целочисленный генератор v1, seed u32
│   │   ├── simulation.goose  # детерминированный шаг состояния
│   │   ├── mesh.goose        # CPU-мешер видимых граней; без gfx/SDL
│   │   ├── stitch.goose      # согласование рёбер и триангуляция без T-стыков
│   │   ├── profiling.goose   # bounded ring, nearest-rank summary, JSON export
│   │   ├── residency.goose   # desired/ready, ближайшая очередь и GPU-резидентность
│   │   ├── paged_world.goose # фиксированный CPU-пул 49 и mapping максимум 81 чанка
│   │   ├── pages.goose       # формат 3, preflight, commit, import/export
│   │   ├── fileio.goose      # объявления тонкого системного I/O
│   │   ├── prepared.goose    # bounded staging, подписи поколений и fallback metrics
│   │   ├── prefetch.goose    # native Goose worker, очереди limit 1, кеш 8 страниц
│   │   ├── player.goose      # фиксированный шаг, AABB, гравитация и прыжок
│   │   ├── interaction.goose # DDA-луч, удаление и безопасная установка
│   │   ├── storage.goose     # GCW v1/v2, транзакционная загрузка и atomic save
│   │   └── visibility.goose  # AABB/frustum без зависимости от gfx
│   └── render/
│       ├── scene.goose       # игровой цикл, ввод, камера и сохранение
│       ├── chunks.goose      # GPU-кеши чанков и бюджет перестроений
│       ├── hud.goose         # прицел, подсказки и собственный bitmap-алфавит
│       └── replay.goose      # детерминированный сценарий SDL/gfx-ввода
├── launcher/goosecraft.cmd   # выбор графического/headless исполняемого файла
├── tests/
│   ├── headless.goose        # блоки, границы и симуляция
│   ├── mesh.goose            # геометрия и ориентация граней
│   ├── player.goose          # движение, коллизии, луч и редактирование
│   ├── region.goose          # стыки, отрицательные координаты, dirty и движение
│   ├── storage.goose         # формат, ошибки и настоящее файловое I/O
│   ├── visibility.goose      # плоскости отсечения и AABB
│   ├── terrain.goose         # генерация, поверхность, приземление и roundtrip
│   ├── stitch.goose          # площадь/цвет треугольников и T-стыки всего мира
│   ├── profiling.goose       # прогрев, rollover, summary и JSON I/O
│   ├── large.goose           # большой мир, GCW v2, копии, движение и геометрия
│   ├── residency.goose       # переходы/смена направления/правки вне GPU-набора
│   ├── paging.goose          # CPU-пул, immutable pages, сбои, checksum и lock
│   ├── prefetch.goose        # AOT-only: warmup, stale results, corrupt data и shutdown
│   ├── support/surface.goose # независимая проверка покрытия меша
│   ├── support/triangles.goose # clipping к единичным клеткам и поиск T-стыков
│   └── fixtures/type_error.goose
├── benchmarks/mesh.goose     # native CPU benchmark: reference/greedy
├── benchmarks/stitch.goose   # reference/raw greedy/stitched, включая 9 чанков
├── resources/windows/       # process UTF-8 manifest, встраивается SDK mt.exe
├── native/fileio.c           # только ограниченное чтение и OS file lock
├── tools/
│   ├── bootstrap.py         # закреплённый Goose и опциональный gfx
│   ├── project.py           # build/test/render-build/render-test/package
│   ├── png_readback.py       # чтение GPU-PNG для проверки границ геометрии
│   ├── profile_readback.py   # независимый пересчёт ns summary из raw rows
│   └── requirements.txt
├── .devcontainer/            # отдельные headless и graphics Docker targets
├── .github/workflows/build.yml
├── toolchain.lock.json      # Goose, gfx, SDL и Nuklear по полным commit SHA
├── docs/validation/          # фактические логи и собственные GPU-снимки
├── licenses/
├── THIRD_PARTY_NOTICES.md
├── AGENTS.md
└── LICENSE
```

`.cache/`, `.venv/`, `build/`, `dist/` — производные, не отслеживаются Git.
Исследовательская копия Horizon не участвует в сборке GooseCraft.

## Границы

```text
launcher ── default ──> goosecraft-client ──> render.scene ──> core.world / core.mesh
         └─ --headless -> goosecraft-headless ───────────────> core
```

`core` использует Goose stdlib, не импортирует gfx и тестируется без сети,
дисплея, SDL, Vulkan или Minecraft-данных. Графический бинарник собирается
отдельно. Headless-тесты не считаются проверкой окна или видеодрайвера.
Лаунчер выбирает процесс и передаёт аргументы, игровых правил в нём нет.

Чанк — фиксированный `u8[4096]`, индекс `x + 16*(z + 16*y)`. В 0.8 владелец
`Map` содержит `Chunk[>..]` последним полем и фиксированные 81 dirty-флаг.
Радиусы 1..4 дают 9/25/49/81 чанк; радиус 0 сохраняет старый диагностический
пул из девяти слотов с активным центром 4. Новый обычный мир имеет X/Z
[-64,80), Y [0,16); размеры старого загруженного мира не меняются.
`div_euclid` отображает отрицательные мировые координаты в чанки.
0 обозначает пустоту,
1 — зелёный тестовый блок, 2 — янтарный. Это собственные идентификаторы,
не реестр Minecraft. `simulation.goose` сохраняет простой консольный счётчик
шагов; игровой клиент использует физику `player.goose` с частотой 120 Гц.

В 0.6 новые миры получают [рельеф v1](terrain-results.md): высота зависит
только от seed и абсолютных X/Z. Генератор заполняет чанки напрямую, без
поблочных dirty-событий и аллокаций; начальная revision равна нулю.
Загрузка существующего GCW v1/v2 имеет приоритет и не запускает генератор.

CPU-мешер отбрасывает внутренние грани и объединяет копланарные видимые грани
одного материала в прямоугольники. На прямоугольник — четыре вершины/шесть u32
индексов; вершина — `float3` и RGBA8. Старый `build_reference` остаётся эталоном.
Тесты разворачивают оба меша в единичные грани и сравнивают точное покрытие,
цвет, ориентацию и отсутствие наложений, включая шум и шахматный худший случай.

Перед GPU upload в 0.6.1 работает `stitch::apply`: отмечает углы greedy-патчей
в сетке 17³, вставляет необходимые точки в длинные рёбра и перестраивает
затронутые прямоугольники в веер. Рёбра на границах чанка дробятся до единичных
отрезков, поэтому независимо перестроенные соседи согласованы. Остальные
прямоугольники сохраняют два треугольника; unit-quads/пустота имеют fast path.
Это всё Goose, без shader bias или изменения размеров блоков. Выход теперь
индексированные треугольники с дополнительными вершинами; `mesh_patches`
обозначает прямоугольники до постпроцесса, а не `vertices / 4`.
Эталон и `--raw-greedy` оставляют исходные quad-меши для сравнения.
[Доказательства покрытия и стоимость](stitch-results.md).

Снимок halo 18³ передаёт мешеру соседние блоки. На стыках внутренние грани
удаляются так же, как внутри чанка. Правка помечает свой и граничных соседей;
повторные пометки объединяются. Начальные активные меши строятся до первого
кадра, далее обрабатываются не более двух грязных чанков за кадр.
У каждого чанка собственный GPU-кеш. GPU-буферы растут по необходимости
и переиспользуются. HUD обновляется по ключу содержимого, обводка — при смене
клетки. `--reference-renderer` включает старые грани и обновления каждый кадр
для автоматической проверки и отключает frustum culling. Это диагностический
режим того же клиента. Основной рендерер отсеивает AABB чанков по шести
плоскостям SDL_GPU clip space; исходные данные мира остаются загруженными.

GPU-слой использует настоящий API goose_gfx: SDL3 GPU, depth buffer, backface
culling, vertex/index buffers и uniform matrix. GLSL содержит только умножение
координат на матрицу и передачу цвета. Нет C/C++ реализации игровой логики.
Меш одинаков для окна и offscreen-режима; пустая сцена служит контрольным кадром.

Goose хранит изменяемые массивы на data stacks; выходы мешера — отдельные массивы
вызывающей функции. Объект с несколькими resizable-полями не предполагается.
В 0.5 это реализовано фиксированным пулом. Для будущего потокового мира нужны
дальнейшие явные владельцы пулов/чанков, а не перенос Rust Arc/heap.

В 0.8 использована подтверждённая возможность Goose: последний член структуры
может быть resizable tail (upstream reference §8, «A resizable tail»).
`Map.chunks` и отдельный массив GPU-кешей имеют фактический размер пула.
Возвращаемые growable значения строятся в месте назначения; передача мира
в игровые функции идёт по `Map&`. O(n) копирование явно помечено `copy()`
в transactional loader и снимках тестов. Backend закреплённого компилятора
не поддерживает `==` для такой структуры, поэтому состояние сравнивает
`world::equal` по metadata и блокам. Тесты проверяют независимость владельцев.
В 0.9 CPU-блоки конечного мира остаются резидентными, GPU-меши имеют
отдельную ограниченную резидентность. `residency.goose` не импортирует gfx:
выбирает квадрат вокруг игрока и ближайший dirty-чанк, хранит ready отдельно
от пустого меша. Рендерер освобождает vertex/index буферы вышедших чанков через
проверенный `gfx::release`, сбрасывает live capacity и geometry counts, сохраняя
накопленные uploads/allocations/rebuilds. Повторный вход строит меш из текущих
CPU-блоков/halo. Начальный набор полон до первого кадра; дальше бюджет два.
Старый dirty вне GPU-набора можно снять: admission всегда ставит новый dirty.
Это не выгрузка CPU-данных или paged storage. [Границы проверки](residency-results.md).

В 0.10 добавлен отдельный `world::Paged` и общий generic игровой цикл для
Map/Paged. CPU-пул 49, logical world slots до 81; это разные индексы.
Один дополнительный слой `pages` загружает CPU до raycast/правок и строит
halo из реальных соседей. CPU-резидентность шире GPU на один чанк, spawn
закреплён. `residency` и GPU metadata обходят logical slots, не размер CPU-пула.
Все codec/policy/gameplay остаются на Goose. Sidecars client/viewer/core.build
компилируют только системный I/O из native/fileio.c. [Спецификация](paged-world-format.md),
[доказательства и ограничения](paging-results.md).

В 0.11 scene отдельно импортирует native-only `core.prefetch`; обычный
`core.core` не требует потоков, поэтому прежние 12 suites продолжают работать
в TinyCC. Worker получает копии Path/PageIndex/Job и не видит изменяемый мир
или gfx. Результат валидирован до отправки, перед admission повторно сверяется
его per-slot generation/hash/count. В `pages::ensure_cached` cache может
заменить preflight и admission без повторного I/O; отсутствие результата
сохраняет прежний safe path. CPU/GPU mapping, редактирование и commit — main.
Сохранения не распараллеливались. [Проверки, затраты и контракты](prefetch-results.md).

В 0.11.1 `prepared::Cache` используется также для успешных preflight-read на main.
Перед переходом сохраняются только валидные, ещё не резидентные страницы целевой
области. Main занимает свободный слот, не вытесняя подходящие worker results.
Оба источника проходят ту же проверку generation/hash/count; `background`
разделяет счётчики `prefetch_hits` и `fallback_reuses`. Ёмкость остаётся 8 страниц;
новый source flag добавляет 8 байт к staging payload. Проверка всех incoming и
commit по-прежнему предшествуют eviction. При большом переходе не поместившиеся
страницы идут по прежнему пути с повторным чтением. `--sync-paging` оставляет
uncached baseline, начальная загрузка также не использует staging.
[Результаты и ограничения](fallback-results.md).

Сохранение — отдельный версионный кодек на Goose. Проверяет весь ввод до
замены мира; GPU-данные восстанавливаются из блоков. F5 и штатный выход
вызывают `write_file_atomic`. Схема и ограничения — в world-format.md.

## Этапы

1. **Инструментарий и headless-основа.** Проверены в облаке, результаты сохранены.
2. **Графическая основа.** Закреплён gfx, добавлены нативный рендерер и проверки
   GPU-readback/окна. Точные границы проверки — в stage-2-results.md.
3. **Играбельный собственный voxel-прототип.** Управление камерой и игроком,
   коллизии, выбор/удаление/установка блока, обновление меша реализованы.
   Headless-физика и графический input replay проверены в облаке; результаты
   и границы Windows-проверки — в stage-3-results.md. Теперь возможен первый
   пользовательский запуск на Windows 10 с реальным видеодрайвером.
4. **Измеримая оптимизация.** Greedy mesh, GPU capacity, кеш HUD и benchmark;
   результаты в optimization-1.md. Пока нет сравнения полного FPS с Minecraft.
5. **Несколько чанков и сохранение.** Соседство, грязные чанки, frustum culling,
   бюджет два чанка, собственный формат и атомарная запись реализованы.
   Точная проверенная область — в multichunk-results.md. Бесконечная генерация
   и потоковая загрузка пока не реализованы.
6. **Лаунчер с UI и доставка.** Версии, настройки, логи и проверка артефактов.
7. **Совместимость Java Edition.** Версионный сетевой адаптер, status/login,
   авторизация и применение серверного мира. Подробный порядок в roadmap.md;
   текущие ID блоков и простая физика не объявляются Minecraft-совместимыми.
